01 / Framing the problem

Model choice is a decision.

The practical question was not whether a sophisticated model could be trained. It was whether it offered useful gains over simpler approaches with very little user data.

01 / TARGET

Personalize from little data

Each test user provides a handful of known ratings. A model must use them to rank 10 other movies that same user has already rated.

02 / TRADE-OFF

Adaptation vs. simplicity

Compare two lightweight baselines against two learning-to-adapt methods to assess when additional training complexity is worth it.

03 / MEASURE

Ranking quality, not hype

Track NDCG, the variability across users, number of episodes, and training and inference time. A perfect NDCG is 1.0.

↳
Why this matters beyond movies: Making decisions from scarce observations is central to many personalization and risk problems. The transferable skill is defining the test, establishing a baseline, and defending a model choice with evidence.

03 / Method selection

Start simple. Earn complexity.

Every method addresses the same few-shot problem, but with different assumptions about how useful preferences transfer between users and items.

BaselineLow training overhead

Linear regression

Fit a new least-squares predictor to each user's support ratings. Tests whether an uncomplicated linear signal in item embeddings goes far enough.

BaselineSimilarity-based

k-nearest neighbors

Use cosine similarity between a query item and the user's support items to average nearby ratings. A fast, interpretable alternative to learned adaptation.

Meta-learningAttention

Matching-network style

Learn an embedding transformation and use soft attention over support items. Trained episodically to predict a new user's held-out ratings.

Meta-learningGradient adaptation

Reptile

Meta-learn an initialization across training users, then take a few support-set gradient steps when adapting to a never-seen user.

04 / Scientific discipline

What I can—and can't—claim.

What was tested: An offline user-disjoint split; 5/10/20 support ratings per test user; up to 10 separate held-out rated items per query; NDCG and timing diagnostics. Model outputs were produced from code, not handcrafted for this page.

What remains unresolved:

  • Archive comparisons are unpaired and come from one experimental run.
  • Ranking only previously rated movies is not full-catalog retrieval.
  • Random user episodes do not model chronological deployment.
  • There is no demonstrated product lift, online A/B test, or causal effect.

The next defensible step is to rerun the paired protocol over multiple seeds, report uncertainty on per-user differences, and add feature ablations and temporal evaluations.

How to inspect the work

The underlying Python pipeline contains dataset loading, self-supervised feature learning, four prediction strategies, episodic training, user-held-out evaluation, CSV reporting, and plots. I included unit tests and a result validator.
